# uq/ — the ported uncertainty modules

TorchUncertainty requires Python >= 3.10 and this audit ran on 3.9, so the three files we need were
ported rather than installed. **These files are not committed** because they are derived from
TorchUncertainty (MIT); copy them from your training host as described in
`../docs/TO_FETCH_FROM_SERVER.md`, or regenerate the risk-coverage one:

| File | Origin | Port |
|---|---|---|
| `nig_layer.py` | TorchUncertainty `layers/distributions.py`, normal-inverse-gamma layer | Added `from __future__ import annotations`; changed cross-file imports; `isinstance(x, A \| B)` rewritten as a tuple. |
| `normal_inverse_gamma.py` | TorchUncertainty `layers/distributions.py` | Same three port fixes. |
| `der_loss.py` | TorchUncertainty `losses/regression.py`, DER loss | Same three port fixes; the loss receives a distribution object, not raw parameters. |
| `tu_risk_coverage.py` | TorchUncertainty `metrics/classification/risk_coverage.py` | Generated by `../scripts/port_risk_coverage.py`. The AURC/AUGRC core is untouched; only the inputs change, from classification (probabilities, 0/1 errors) to regression (confidence, `|y - y_hat|`). |

**What the port does not change:** the evidential mechanism itself — the normal-inverse-gamma
parameterization, the DER objective, and the AURC/AUGRC algorithm are exactly as released. Only
Python-version compatibility changed.

Usage note: `NormalInverseGammaConvNd(base_layer=nn.Conv2d, event_dim=3, in_channels=..., kernel_size=1)`.
`out_channels` is derived automatically as `4 * event_dim` — do not pass it. `forward` returns a dict
with keys `loc`, `lmbda`, `alpha`, `beta`.
